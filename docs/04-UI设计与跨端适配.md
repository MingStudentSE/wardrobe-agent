# wardrobe-agent UI 设计与跨端适配

## 1. Hallmark 作为 UI 设计技能

使用 [Nutlope/hallmark](https://github.com/Nutlope/hallmark) 进行 UI 设计、实现、审查和重设计。它是设计技能，不是运行时 UI 组件库，也不限定前端框架。

项目级安装：`.codex/skills/hallmark/`，上游提交 `13ac0ec7e148655948100b6396439e481361d690`。保留上游 MIT LICENSE 和来源记录；更新需显式审查。后续 Agent 通过技能名 `hallmark` 使用能力，先读取其规则及当前任务需要的参考文件。

先根据衣橱操作场景选择视觉方向，再建立命名 tokens：颜色、字体、字号、间距、圆角、边框、动效与组件状态。产品以衣物图片、库存信息和任务反馈为中心。中文字体、长名称和数据密度须实际预览。

确定视觉系统后，后续页面沿用相同 tokens 和组件语义；Hallmark 的主题轮换用于探索不同方向，不用于让同一应用每个页面变换风格。页面结构随任务变化，视觉语言保持一致。应用工作流不强行套用营销页面的 hero、CTA 或 footer。

## 2. 交付范围

- Beta 只设计、实现和发布桌面应用；支持可调整窗口与键盘/鼠标操作。
- 后续明确扩展 Android；现在就规划窄屏布局、触摸操作和视觉一致性。
- 窄屏预览用于验证适配基础，不代表 Android 应用已完成；Android 打包、权限、系统返回、照片导入和后台行为需后续真机验证。
- Android 技术路线仍待原型验证；共享领域核心、协议、视觉语义与设计 tokens，不预先承诺所有 React 组件可原样迁移到原生 UI。

## 3. 共享风格与适应布局

| 对象 | 共享内容 | 桌面 Beta | 后续 Android |
| --- | --- | --- | --- |
| 视觉系统 | 色彩角色、字号层级、图标语义、间距节奏与状态颜色 | 鼠标与高密度展示 | 触摸与可读性优先，映射到平台尺寸单位 |
| 导航 | 功能分组、命名、当前成员与页面状态 | 侧栏与键盘导航 | 根据一级入口数量采用底部导航或导航抽屉 |
| 衣橱 | 图片比例、单品身份、筛选与排序语义 | 自适应多列网格、可展开筛选 | 减少列数，筛选使用抽屉或 sheet |
| 详情与编辑 | 字段顺序、校验、保存与恢复语义 | 空间足够时列表/详情双栏 | 单列详情和分步返回，保留草稿 |
| Agent 与长任务 | 上下文、进度、取消、重试和待确认状态 | 空间足够时并排显示 | 单列切换，关键动作保持可达 |
| 系统能力 | 能力接口与错误语义 | 文件选择、拖拽、快捷键 | 系统照片选择、相机、触摸；平台适配器提供能力 |

断点由内容可读性决定，窄屏基础样式向宽屏增强。布局、展示密度与交互能力分别处理；不能用窗口宽度推断是否有鼠标。

图片网格使用可收缩轨道；正文、长中文名称和空状态不撑破容器。对话与编辑考虑软键盘、安全区和可变视口高度。表格在窄屏提供可读的列表或详情表达。

## 4. 交互与可访问性

每个操作有明确的默认、hover、焦点、按下、禁用、加载、错误和成功状态；不适用的状态在组件规范中说明。键盘可完成桌面关键流程，焦点可见；触摸可完成同一流程，hover 信息有点击/焦点等价入口。

拖拽录入提供文件选择替代；图标按钮有可访问名称。触摸目标按 Android 平台规范映射，初始设计以至少 48dp 为目标。字体放大后动作仍可达；状态不只靠颜色区分。动效遵守减少动画偏好，传达状态变化而非装饰。

删除/归档继续遵循现有产品要求：位于详情或编辑页，使用备份、回收站和恢复；不因技能推荐乐观更新而改变这些约束。

## 5. UI 交付验收

每次涉及 UI 的交付附实际界面截图/预览及验证记录：

- 桌面：至少检查 1024、1280、1440 CSS px 宽度及窄窗口；验证键盘、焦点和窗口缩放。
- 适配基础：按 Hallmark 要求检查 320、375、414、768 CSS px 宽度；不出现页面级横向溢出、动作被遮挡或仅 hover 可操作。
- 核心流程：衣橱浏览、筛选、单品详情/编辑、图片录入、Agent 对话与任务进度。
- 状态覆盖：空库存、长名称、多图、加载、失败、重试、离线和保存反馈。
- 主题/字号：验证实际支持的主题、中文排版、系统字体缩放与减少动画。

尚无 UI 实现，本次只落地技能和规范；不声称任何视口或 Android 真机验收已通过。
