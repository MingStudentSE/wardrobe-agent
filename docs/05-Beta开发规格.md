# wardrobe-agent Beta 开发规格

2026-10-07。本文将用户确认的交付范围与工程负责人确定的实现默认值分开记录。与旧文档的首版/阶段描述冲突时，以本文及用户最新明确要求为准。工程默认值可根据实现验证调整，但不得因此删减用户确认的功能。

## 1. 用户确认的交付范围

- Beta 交付需求清单中的全部 F01–F30，覆盖 GUI、CLI、MCP 所列能力。内部按阶段开发，所有阶段完成后才算 Beta 交付，不将部分功能标为未来版本来缩减范围。
- 本轮提供 macOS DMG，完成 macOS 安装、升级、数据保留与恢复验证；Windows EXE、Linux DEB 及对应平台实测延后，保留跨平台架构。
- Android 后续交付；Beta 已包含共享协议、视觉语义、窄屏和触摸适配基础，不要求 Android 安装包。iOS 不列本次承诺。
- 产品开源；不设收费功能、付费生成入口、订阅、充值、项目代收费用或会员权限。模型通过用户自行配置的 API 或本地模型调用，消耗其供应商账户额度；产品开源不意味着供应商 API 免费。
- 所有业务操作能力都提供，不以会员/付费层级限制 GUI、CLI 或 MCP。保留成员范围、类型校验、设备配对和本机客户端授权，防止误操作和跨成员写入。
- 不做家庭邀请、多人协作、共享角色、协作者访问控制或家人评价。独立成员档案保留。
- S3-compatible、WebDAV、本地文件夹为 Beta 同步后端；其他云盘是后续适配扩展。REST、自建云、Web 入口、原 Obsidian 数据导入不纳入已确认的 F01–F30 必交范围中的可选扩展。

## 3. 字段与默认规则（工程确定）

### 3.1 通用与单品字段

所有实体使用 UUIDv7、schema_version、created_at、updated_at；日期时间以 UTC 保存，实际穿着/洗护另存当地日期和 IANA 时区。价格使用最小货币单位整数及 ISO 币种，禁止浮点金额。

单品必填：id、member_id、name、category、status；name 去首尾空白，1–120 字符，缺名称的草稿默认“未命名单品”。无照片可保存，展示占位图。必填不代表必须手工输入 ID。category 未知可选 other，status 默认 active。

- category 使用成员自己的分类注册表；默认提供 top、bottom、outerwear、dress、one_piece、shoes、bag、accessory、underwear、sportswear、other，允许通过 category.create / category.delete 新增和删除。新增分类使用稳定 custom_UUID ID；删除分类将已有单品转入 other，保留历史穿搭快照；other 不可删除。sub_category 为可选自由文本。参见 docs/api/categories.md。
- seasons 固定 spring/summer/autumn/winter 多选，空数组表示未知或未设；“四季”展开为四项。
- color、pattern、material、style、occasion、tags 为可编辑多值；颜色使用稳定 ID + 可选用户描述。数组按规范化键去重，保留展示文本。
- brand、size_label、fit、description、notes 为可选文本；notes 上限 10000 字符。尺寸数值使用独立 measurement + unit，不让 LLM 从图片推断真实尺寸。
- purchase_price_minor、currency、purchase_date 为可选；价格非负，提供价格必须有币种。尺寸/购入日期未知使用 null，不填 0 或当天冒充事实。
- status 为 active/archived/deleted；favorite 独立布尔。待洗是派生状态，不混入生命周期 status。恢复保留收藏、历史和资产引用。
- display_asset_id、图片关联和排序可为空；每单品最多 20 张关联图片，每批最多 100 个文件，JPEG/PNG/WebP/HEIC 为导入目标，单文件上限 50 MiB、解码上限 60 MP。解码不支持或超限给出逐项错误，不删原文件。
- AI 建议单独存建议值、provider/model、时间、来源资产及不确定项。人工确认后才写事实；用户修改优先。未校准的模型自报分数标为模型自报，不当作准确率。

### 3.2 搭配、穿着、洗护与统计

- 搭配 name 1–120 字符，至少一个真实单品；单品不能重复出现，必须属于同一成员。角色与层次单独存储；手工保存可接受不完整组合，推荐必须按场合明确缺失角色。
- 穿着一次由一个 WearEvent 表达，包含成员、日期、时区、单品快照、可选搭配来源及用户备注。允许同日换装多次；同次重复点击/重试通过操作幂等键去重。
- wearCount 按有效事件中单品出现次数计算；wearDays 按当地日期去重另算。同日两次穿同一件是两次穿着、一天穿着，界面明确口径。未来日期不能记录实际穿着，计划与实际分开。
- 更正/撤销生成引用原事件的新事件；修改、删除单品或模板不改写历史快照。长时间未穿默认 90 天，可配置；从未穿过单独展示。
- 每件衣物 wash_after_wears 可设为正整数或 null，默认 null（不猜洗护周期）。达到阈值或用户手动标记即待洗；洗护后从最近有效清洗事件重新计数。补记/撤销穿着或洗护后按时间顺序重算。
- 洗护记录支持 wash/dry_clean/maintenance；wash 与 dry_clean 重置洗护计数，maintenance 默认不重置。用户可修改阈值和手动标记。
- 总体/舒适/风格评分为 1–5 可选整数；喜欢/不喜欢/跳过与真实穿着分开。学习画像可查看、修正、重置，不改动事实事件。

### 3.3 推荐、任务与调度

- 默认返回 3 套不同有效方案，范围 1–5；不足时返回实际可行数量和原因。固定单品不替换；待洗、归档、删除单品不作为自动推荐候选。固定项不可用时说明冲突，不悄悄放宽约束。
- 避免近期重复默认回看 7 个当地自然日，为软约束；库存不足时明确说明放宽情况。成员、存在性和必选/排除为硬约束。
- 天气地点手动设置，可关闭天气并填写温度/场合；缓存显示获取时间，超过 3 小时标过期。天气失败不阻断手选场合或离线规则推荐。
- 内置 Agent 支持今日穿搭、场景/旅行计划、分析和购买适配；候选购买草稿不计入库存，计划不计为穿着。
- jobs 状态沿用架构定义；瞬时网络/限流错误默认最多自动重试 2 次并遵守 retry-after；认证、参数或能力错误不自动重试。生成请求结果未知时先查 provider 状态，无法查询则标记待核对，不盲目再提交消耗额度。
- 定时计划保存成员、当地时间/时区、星期、场合、执行设备和启用状态。恢复时默认补执行最近 2 小时内的到期计划，每计划最多一次；更旧任务标记错过而不集中发送。用户可配置补执行窗口。

## 4. 操作能力与 API 额度

所有已授权业务能力在 GUI/CLI/MCP 提供；外部客户端授权可包含完整读写、图片上传/生成、同步、备份、恢复与学习重置，无付费分层。用户在本机连接客户端时选择完整授权或限定 scope，完整授权后在范围内不逐次弹重复权限确认。

- 查询、推荐、手工录入/编辑、搭配保存、反馈和用户明确表达的穿着/洗护记录按指令执行。
- 图片生成与模型调用使用已配置的 provider/model/凭据；用户显式点击、指令或启用计划即授权对应调用。提供任务进度、取消、失败原因及可获得的 token/请求用量，不虚构余额或价格。
- 原图可按用户的识别/生成指令发送给其模型 provider，但不进入设备同步；同步白名单与云模型上传是两条不同通道。采用生成图后才替换当前展示图。
- 不做应用收费页或“付费生成”按钮；无凭据、额度不足、限流均作为 provider 配置或调用错误处理。
- 删除使用回收站，入口在详情/编辑；恢复预览展示范围。永久清理、覆盖恢复和密钥更换使用明确的专门动作，不从普通推荐或模糊对话触发。全部操作能力不等于绕过成员范围、校验或同步资产白名单。

## 5. 三平台工程支持基线

初始验收基线：Windows 11 x64、macOS 13+ Apple Silicon/x64、Ubuntu 22.04/24.04 x64 DEB；最低版本属于工程默认值，须用实际构建与依赖验证，发现不支持则修正文档并记录原因。当前仅 macOS 进入 Beta 发布门槛；Windows/Linux 基线保留为后续工程目标，构建、安装与发行实测延后，不阻塞本轮。macOS 各声明支持架构必须有实际验证记录，未验证架构不得宣称已支持。

API 支持：文本/视觉 OpenAI-compatible 可配置端点、模型和安全凭据；图像生成及试穿使用明确 capability 的适配器，覆盖 F05/F07/F09/F15/F16/F17 的真实可用调用。首次实现选择能覆盖上述能力的 provider 做真实集成验证，并记录模型、接口和输入限制；无需每个平台都调用全部供应商。不承诺任意自称兼容的 API 可支持全部图片能力。

没有 API key 的用户仍能完成全部手工、离线统计、本地拼贴和规则兜底流程；云 AI 能力显示配置入口。开源许可证选择与第三方许可清单在对外发布前完成；当前 GitHub 仓库仍为私有，不因“产品开源”表述自动改变可见性。

## 7. 质量与发布门槛（工程确定）

- 正确性：已知领域 fixture、三入口一致性、同步冲突/去重、崩溃恢复、迁移与备份恢复全部通过；不出现丢衣物、丢历史或重试重复记账。
- 隐私：扫描本地普通配置、日志、导出和同步包，无 API key、密码或被禁止同步的资产/EXIF/GPS；模型上传对象与用户操作一致。
- 性能：每平台记录测试机器；在 4 核 CPU、8 GB RAM、SSD 基线及 10000 单品/100000 穿着事件 fixture 下，冷启动到衣橱可交互 ≤5秒，本地搜索/筛选首屏 p95 ≤500ms，普通实体保存 p95 ≤300ms（不含图片/网络）。各采样至少 30 次，记录实测与环境，不把云模型响应纳入本地性能保证。
- 图片：固定至少 20 张含白衣、细纹、印花、旋转和大图的样本；压缩前后并排人工检查，不损坏可辨细节；遵循架构的软体积阈值，原图字节不变。
- UI：`ui-ux-pro-max` 审查及 04 文档全部视口、键盘、触摸等价入口、空/加载/失败状态验收；不只检查静态首页。
- 平台：各目标系统真实安装/升级/恢复，GUI/CLI/MCP 可独立运行；Android 仅验证适配基础，不计为真机完成。
- 发布：F01–F30 全通过、有可下载 macOS 产物、许可与依赖清单、已知限制、迁移说明和测试报告后才能标记 Beta 完成。凭据不可用的 UI 提示不替代云 AI 的真实成功验证。

## 发行范围调整（2026-10-07）

2026-10-07 用户范围调整：当前完整 Beta 仅发行和验收 macOS；Windows/Linux 安装包、真实客户端运行与发行验收延后，不阻塞本轮 Beta。F01–F30 功能范围保持；共享 Rust Core/Application API、GUI/CLI/MCP 协议与版本化数据模型保持跨平台，路径、凭据、通知和系统集成封装在平台适配边界，不向业务核心引入 macOS 专属依赖。跨平台架构审查不等于 Windows/Linux 已构建或验收。
