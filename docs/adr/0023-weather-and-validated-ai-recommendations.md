# ADR 0023: Configured weather and validated text recommendations

Status: accepted implementation decision; acceptance requires independent verification.

Weather uses an explicit member location and coordinates. Off and manual temperature/occasion remain available. No location is inferred. The free Open-Meteo adapter is an explicit noncommercial option; the application does not purchase a plan. Estimates retain source, provider valid time, retrieval time, attribution, and error. A cached estimate becomes stale strictly after three hours. A failed refresh retains the previous estimate and permits offline rules. A configuration compare-and-swap prevents a late refresh from restoring a disabled or changed location.

The text model organizes candidate sets produced by the existing rule planner. It receives bounded candidate facts and controls, never original images, local paths, secrets, or an unbounded database dump. Candidate preparation does not persist another recommendation intent. The same planner validates body coverage, current member availability, fixed/excluded IDs, roles/layers, recent wear and cold-weather outerwear again after the network call. Replace/change preserve retained immutable metadata. Saving a recommendation creates a template, never a wear event.

Plain compatible chat is the default. JSON object and llama.cpp JSON schema modes require explicit selection; no unsupported structured parameter is silently imposed on generic providers. Two confirmed invalid model outputs permit at most two output attempts. Confirmed HTTP 429 rejections have a separate global budget of at most two automatic retries per job, honoring numeric or HTTP-date Retry-After. These counters survive worker restart; together they permit at most four provider submissions. Unknown network outcomes never receive blind retries; confirmed exhaustion and nonretryable errors fall back to rules. Model explanations are unverified text and do not alter clothing facts.

The initial AI generate/replace/change call immediately returns a persisted member-scoped `text_recommendation` job_id before weather, catalog construction or provider HTTP. `recommendation.worker.run` is explicitly executable through CLI/MCP; GUI starts that worker, polls jobs.get and offers cancellation. Completed jobs reference an immutable intent for explicit saving. A persisted job claims a lease before any network work. The transaction records submission before POST. Two connections with the same operation key cannot submit twice. A subsequent POST is permitted only after confirmed invalid output or confirmed 429, with a valid current lease and a persisted remaining budget. Rate-limit waits of up to thirty seconds check cancellation/expiry every fifty milliseconds; longer hints persist next_due and release the worker instead of blocking indefinitely. An explicit worker may resume when due, and the active GUI drives these queued jobs. Retry-After is never shortened to obtain an early retry. A submitted request with unknown outcome cannot be blindly retried after a crash; generic chat has no outcome query, so the caller must check the provider or explicitly select offline rules/new intent. Submitted expired leases move to waiting_input. Cancellation/expiry prevents publication, checked in the same IMMEDIATE transaction that inserts the intent. If cancellation occurs after that commit but before job completion, the already published intent remains authoritative and same-key receipt references it without another network call.

Schema 18 adds only persisted weather preferences. Jobs reuse the existing table. Table presence is repaired even when user_version already reaches a newer module version. Weather cache is derived; future sync should export configuration explicitly rather than provider/cache/request credentials.

Primary references: [Open-Meteo forecast protocol](https://open-meteo.com/en/docs), [free-service terms](https://open-meteo.com/en/terms), [official llama.cpp server protocol](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md), [official Qwen GGUF model and license](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct-GGUF).

Actual local model selection proves legal IDs for one public synthetic wardrobe, not general styling accuracy. Paid cloud providers, native platform GUI execution, and full Beta platform gates remain separate evidence requirements.
