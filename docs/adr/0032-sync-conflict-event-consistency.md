# ADR 0032：同步冲突、删除与事件一致性的因果裁决

状态：已实施；分支 `codex/ticket-28-conflicts`（基于集成分支 tip 6301175），红/绿证据在 `wardrobe-execution/results/continue-20261007/ticket28/`。

## 背景

#27 交付了按发布顺序正确的双设备同步，并把 `sync_fields` 变体寄存器、`sync_immutable` 历史分支与 `status=deleted` 优先裁决留作接口；#28 在其上完成冲突检测与解决的真实语义：字段/集合冲突、删改冲突、恢复、事件去重、乱序与离线后的收敛，以及画像一致与同步不回声。

## 决策

- **因果版本检测并发，不用时间戳裁决事实。**每个同步操作携带创建时的因果 base 与自增 clock；字段寄存器按支配关系剪枝（被支配候选移除、互不支配候选全保留）。日志 op_id 由触发器生成随机稳定标识，仅作未解决时的暂定显示排序，不承载时间语义；本地墙钟偏差、到达顺序、重复投递都不改变保留的事实集合。未解决时两端显示一致的暂定值（同序排序的同候选），不脑裂。
- **同字段不同值保留双方并可解决。**`sync_fields` 变体（值+clock+op_id）经 `sync.conflicts` 对外可见（含预期令牌 `expected_token`）；`sync.resolve` 以乐观令牌 + 幂等操作键显式选择，解决结果经正常领域事实回流对端，收据幂等重放。事件/搭配版本等不可变事实的并发修订继续走 `sync_immutable` 分支审查（`field=branch`）。
- **集合按元素操作语义。**颜色/图案/材质/风格/场景/标签/季节登记为逐元素存在性（`present/label`），不做整值后写覆盖：并发添加互不丢失，同元素并发添加只计一次，一增一删按添加可见合并。
- **搭配（outfit）结构冲突人工处理可见。**并发 `items` 编辑进入变体冲突并在同步设置面板展示（候选按单品/角色渲染）；解决方式是显式重新发布搭配版本，并发版本历史保留 `sync.history` 可查。
- **删除优先、副本保留、恢复显式。**字段裁决中 `status=deleted` 优先于并发候选：迟到编辑不复活已删事实，编辑值保留为 lifecycle 冲突副本；`sync.resolve` lifecycle `value=active` 是唯一恢复路径（`restore_required` 拒绝静默复活），恢复保留并发编辑并回流对端。
- **乱序挂起、重复幂等、计数口径不变。**因果前序或依赖实体未到达时事件进入 pending 公平重放（不静默丢弃、不无限循环）；重复投递按 inbox op_id 幂等只应用一次。穿着次数按有效事件、天数按当地日期去重的既有口径在乱序/重复场景下保持正确；未解决的并发修订分支使派生计数显式失败（`sync_conflict`）而不是给出武断数字。
- **画像收敛且不再生成同逻辑 outbox。**对端事实经 inbox 收据与发布标记只应用/转发一次；冲突解决、恢复与画像重算只写本机 outbox/审计，不生成同逻辑同步日志。收敛后重复同步 sent=received=0；两空间对同一事件集重算的画像 `inferred`/`pair_projection` 一致。

## 测试与证据

- 新公开回归 `crates/wardrobe-core/tests/sync_conflict_consistency.rs`（5 个真实双安装 ignored 测试）：迟到编辑不复活删除+冲突副本+显式恢复、字段合并+集合并发增删不丢+同字段双方可解决、搭配结构冲突可见+显式更新收敛、到达顺序不裁决事实+因果支配直接收敛、离线重连+乱序挂起+重复投递+事件计数+画像一致+零回声。
- GUI：同步设置面板冲突入口（既有）+ 搭配结构冲突候选可读化（不再出现 `[object Object]`），`apps/desktop/tests/sync.spec.ts` 扩展结构冲突可见与人工处理收敛流程。
- CLI/MCP：`sync.conflicts`/`sync.resolve` 经既有 descriptors 与 `crates/wardrobe-cli/tests/entrypoints.rs` 覆盖，无新增私有入口。
