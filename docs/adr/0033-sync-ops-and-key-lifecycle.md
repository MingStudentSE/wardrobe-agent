# 0033: 同步运维与密钥生命周期（暂停/换目标/镜像/水位回收）

日期：2026-10-07（issue #31）

## 背景

#27/#28/#29/#30 交付了真实双设备增量同步（本地文件夹/S3-compatible/WebDAV）、冲突一致性与纪元化传输，但留有三类运维缺口：同步批次不可暂停、更换目标会孤立全部已发布对象、`sync_asset_commits` 已处理键登记与远端改动日志（tombstone）永久膨胀。本票在共享 Application API 上补齐运维闭环，GUI/CLI/MCP 自动同源。

## 决策

1. **暂停是本机主目标文档内的持久开关**（`sync.pause`/`sync.resume`，文档字段 `paused`）。`sync.run` 入队与 `sync.process` 领取前都以 `sync_paused` 显式拒绝；暂停前已入队的任务保留，恢复后同一任务继续。暂停只作用于本机目标，不向对端传播。
2. **更换目标 = 先复制校验，后原子切换**（`sync.target.switch`）：目标构造复用 `sync.configure` 的真实连接 + 能力探针；复制按已知平铺目录（`changes`/`blobs`/`epochs/{e}/changes|blobs|watermarks`、`epochs/{e}/index/{当前配对发布者}`）逐对象进行，新写入对象回读比对 sha256，已存在对象逐字节对账。全部通过才在一个事务里切换主目标文档并搬迁按目标键索引的传输状态（`sync_cursors`/`sync_publications`/`sync_pending`/`sync_quarantine`/`sync_index_*`）；任一步失败保持旧主目标（回退 = 旧目标原样可用，不清理旧目标任何字节）。
3. **单调对象向前合并**：发布者页游标 `head.index` 与设备水位记录会合法前进。复制对账发现同名不同字节时，仅允许这两类对象「向前合并」——解密双方取更前进者回写目标，同页码不同摘要/同水位不同字节仍视为损坏冲突并整体失败；其余对象字节不一致一律中止。
4. **镜像备份是单向副本，不做多主**（`sync.mirror.configure/sync/promote/remove`）：镜像完整复制主目标并逐对象校验；增量补齐幂等。主目标不可用时显式「提升」——先校验镜像与主目标逐对象一致、再校验镜像内 changes 发布标记可解密且与对象字节自洽，通过后交换主/镜像；旧主目标原样保留（带 `degraded` 标记），可再次提升切回。镜像不参与对端协调；各设备各自指向自己的主目标。
5. **安全回收按设备水位，绝不按固定时间盲删**（`sync.reclaim`）。op_id（触发器随机 UUID）不保证时序，可靠的单调进度是**发布者索引页位置**：每设备在 `sync_index_read.next_page` 里已维护「对每个发布者已完整消费的连续页前缀」。同步步末设备把 `{positions, captured_at}` 加密发布到 `{space}/epochs/{e}/watermarks/{device}.commit`（best-effort，失败只让水位偏旧，方向安全）。回收同时要求三个条件，缺一不可：
   - 全部当前配对设备都有水位记录，且该发布者页号 < 所有设备位置的最小值（页粒度整页回收，标记先删、对象后删）；
   - 全部水位捕获时间早于保留窗口（默认 30 天，输入 `retention_seconds` 可配置），窗口从「所有设备都已确认」时刻起算，覆盖离线回连与备份恢复；
   - 调用方显式 `backup_confirmed=true`（确认存在覆盖被回收范围的本地备份或加密快照包），否则 `sync_reclaim_baseline_required`。
   水位无法覆盖全部设备时结果如实列出 `blocked_by`。**远端 blob 对象不回收**：新设备引导与恢复备份都依赖目标上完整的展示图 commit；blob 只清理「远端对象已消失」的 `sync_asset_commits` 死行（每批有界），使已处理键登记不再永久膨胀。
6. **凭据生命周期**：`wardrobe-agent.sync` 钥匙串条目按 target_key 隔离。纪元推进（撤销/轮换）会滚动目标键（强制按新纪元重新发布），入队时把 WebDAV 密码 / S3 访问键**自动迁移到新目标键**（旧键保留供回退），所有者与重配置后的设备都无需重输凭据——语义在能力描述与本 ADR 如实声明。`encryption.unpair` 与 `backup.restore` 现在清理这些凭据并清空按目标键的传输状态（此前 unpair 不清理，条目按 target_key 累积）。
7. **撤销设备的同步语境**：撤销即纪元轮换致盲——所有者新事实只进入新纪元命名空间，被撤销设备停留在旧纪元视图（可读自己的旧数据，不再取得任何新事实，写入无读者）；设备状态协议送达新清单后（`encryption.device.apply`）该设备自锁（`revoked`），此后同步以 `device_revoked` 显式拒绝。改密码只重包装本机钱包、不影响空间密钥，同步照常；错误密码恢复失败不破坏现有状态。
8. **状态页**：`sync.status` 新增 `paused`、`mirror`、`cursor`（已消费提交数/最后消费 op）、`watermark`（本机页位置水位与捕获时间）、`last_failure`（仅当最近一次同步结果是失败；显式重试成功后恢复干净）、`last_reclaim`。GUI 在同步设置面板内只读展示并提供暂停/恢复、重试失败批次、切换目标（复制校验）、镜像建立/增量/提升/移除与带备份确认的回收入口；CLI/MCP 经共享 descriptors 自动获得。

## 后果

- 更换目标与镜像提升是原子的、可回退的；复制校验的成本与空间成正比，Beta 规模可接受。
- 回收不处理旧纪元目录（无法解密验证；新纪元设备本就不读），留待人工清理或未来票。
- 晚于保留窗口加入的全新设备须先恢复备份基线再同步前推（与纪元轮换的再发布规则一致）；页游标消费路径对缺失提交进入 `sync_missing` 并在状态页可见，不会静默跳过。
- 已知限制：非本机目标的镜像 target_key 不含纪元分量（与 configure 派生一致），跨纪元复用同一镜像配置时以最后写入为准；多主协调按规格明确不做。
